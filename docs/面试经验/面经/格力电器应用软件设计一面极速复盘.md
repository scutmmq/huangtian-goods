### Q2：RAG 原理（OpsMind 企业数字员工）
* **核心答题框架（四步闭环）**：
  1. **文档加载与分块（Indexing & Chunking）**：针对企业内部运维知识库（PDF/Markdown/Word），采用多级递归分块策略（Chunk Size = 512，Overlap = 64），保留标题层级与上下文连贯性；
  2. **向量化与存储（Embedding & Vector DB）**：调用文本嵌入模型（如 BAAI/bge 或 text-embedding-3）将文本块转化为高维稠密向量，存入 PostgreSQL 的 `pgvector` 插件中构建 HNSW 索引；
  3. **检索与重排（Hybrid Retrieval & Rerank）**：用户提问时，采用 **BM25 关键词检索 + 向量语义检索** 双路召回，通过 RRF（倒数排名融合）或 Cross-Encoder 重排模型选出 Top-K 最相关的切片；
  4. **生成与溯源（Generation & Citation）**：将用户问题与召回切片组装成带有严格防幻觉 Prompt 的上下文，喂给大模型（LLM）生成答案，并输出精确到原文档段落的引用溯源。

### Q4：视频巡检拍照是如何做的？（云智易实习）
* **核心答题框架（设备拉流 + 调度架构）**：
  1. **设备通信与协议层**：系统通过海康 IPC 摄像头的标准 **RTSP 协议**（Real-Time Streaming Protocol）拉取实时 H.264/H.265 视频流；
  2. **关键帧抓拍与解码**：借助底层流媒体 SDK 或 FFmpeg 抓取实时关键帧（I 帧），在内存中解码并临时转化为图片流；
  3. **任务调度层（单线程 → 专属线程池 → XXL-JOB 分片）**：
     * **早期痛点**：单线程 `for` 循环轮询，遇到单台摄像头网络超时直接阻塞 5 分钟；
     * **重构方案**：基于 **XXL-JOB 分片广播** 将园区数百台摄像头按机器节点均匀分摊，节点内部通过 **专属业务线程池（Core=8, Max=8, ArrayBlockingQueue=500, CallerRunsPolicy）** 异步并发抓拍，结合利特尔法则（$QPS \times RT$）与边缘硬件解码通道上限（8~16 路）精准推导参数，单轮巡检耗时从 5 分钟压缩至 **25 秒以内**，彻底消除单点长尾阻塞。

### Q5：Java 进程和线程的本质区别？
* **五大维度满分对照**：
  1. **定义与归属**：**进程是操作系统资源分配的基本单位**，拥有独立的虚拟地址空间、文件句柄和系统资源；**线程是 CPU 调度执行的基本单位**，是进程内的执行流，一个进程至少包含一个线程；
  2. **内存空间与数据共享**：
     * 进程间内存完全隔离，互不干扰（IPC 需通过管道、共享内存、套接字等）；
     * 同一进程内的多个线程**共享堆内存（Heap）和方法区/元空间（MetaSpace）**，但每个线程拥有独立的**程序计数器（PC Register）、虚拟机栈（JVM Stack）和本地方法栈**；
  3. **开销与上下文切换**：进程切换涉及虚拟地址空间和页表（Page Table / TLB）的切换，开销巨大；线程上下文切换只涉及 CPU 寄存器和栈帧状态，轻量且速度快；
  4. **安全性与健壮性**：一个进程崩溃不会直接导致另一个进程崩溃；但在 Java 中，一个线程发生未捕获异常抛出 `Error`（如 `OutOfMemoryError`）或死锁可能拖垮整个 JVM 进程；
  5. **通信开销**：线程间直接通过共享内存变量通信（配合 `volatile / synchronized / CAS`），速度远高于进程间通信。
