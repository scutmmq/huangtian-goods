## 🎯 模块一：Java 基础语法与代码输出陷阱（必考 8 大题型）

### 1. 类初始化与继承执行顺序（代码输出题第 1 高频）
* **【绝对执行公式】**：
  $$\text{父类静态（块/变量）} \rightarrow \text{子类静态} \rightarrow \text{父类实例代码块/成员变量} \rightarrow \text{父类构造器} \rightarrow \text{子类实例代码块/成员变量} \rightarrow \text{子类构造器}$$
* **【两大必考避坑点】**：
  1. **静态块只在类加载时执行 1 次**，后续 `new` 多个对象时绝不再执行；
  2. **多态调用**：**普通成员方法看右边（动态绑定执行子类重写方法）；成员变量与静态方法看左边（编译期静态绑定，取声明类/父类的值）**！

---

### 2. `try-catch-finally-return` 执行流与返回值
* **规则 1**：`finally` 块中的 `return` 会**彻底覆盖** `try` 和 `catch` 中的任何返回值与未捕获异常；
* **规则 2（基本类型）**：`try { return i; }` 在执行前会将 `i` 的值复制暂存在操作数栈底，即便 `finally { i++; }`，**最终返回值依然不变**；
* **规则 3（引用类型）**：`try { return sb; }` 暂存的是堆内存引用地址，若 `finally { sb.append("B"); }`，**返回值的内容会改变**；
* **规则 4**：只有 `System.exit(0)` 或 JVM 崩溃时，`finally` 才不会执行。

---

### 3. 自增自减陷阱（`i = i++`）
* **经典绝杀题**：
  ```java
  int i = 0;
  i = i++; 
  System.out.println(i); // 输出 0 !
  ```
* **JVM 底层原理**：先将 `i` 的初始值 0 压入操作数栈，然后局部变量表中的 `i` 自增变为 1，最后将操作数栈顶的 0 弹出赋值给 `i`，导致自增后的 1 被覆盖回 0。

---

### 4. 包装类缓存机制与自动拆装箱
* **缓存区间清单**：
  - `Byte`, `Short`, `Integer`, `Long`：缓存 **`[-128, 127]`**；
  - `Character`：缓存 **`[0, 127]`**；
  - `Boolean`：缓存 `TRUE, FALSE`；
  - `Float`, `Double`：**完全没有缓存**（每次赋值都 `new` 新对象）。
* **自动拆箱规则**：两个包装类用 `==` 比较的是对象地址；**只要有基本数据类型参与 `==` 比较，必定自动拆箱为数值比较**。

---

### 5. `String` 常量池与拼接规则
* **常量折叠**：`String s = "a" + "b";` 编译期直接优化为 `"ab"`，指向常量池；
* **含变量拼接**：`String s1 = "a"; String s2 = s1 + "b";` 运行期通过 `StringBuilder` 拼接，**在堆上生成新对象**；
* **`new String("abc")` 对象数**：常量池若已有 `"abc"` 则只在堆上创建 **1 个**；若没有则在常量池和堆上各创建 1 个（共 **2 个**）；
* **`s.intern()`**：返回字符串常量池中的引用。

---

### 6. 位运算与移位操作（`>>` vs `>>>` vs `<<`）
* **`<<`（左移）**：二进制全部左移，低位补 0，相当于乘以 $2^n$；
* **`>>`（算术右移）**：高位补**符号位**（正数补 0，负数补 1），相当于除以 $2^n$；
* **`>>>`（无符号右移）**：无论正负，**高位一律补 0**（负数无符号右移会变成极大的正数）。

---

### 7. 数据类型转换与溢出截断
* **类型自动提升**：`byte, short, char` 在进行算术运算时，一律先自动提升为 **`int`** 再计算！
  ```java
  short s1 = 1;
  s1 = s1 + 1; // ❌ 编译报错！s1 + 1 变成了 int，赋给 short 需要强转
  s1 += 1;     // ✅ 编译通过！+= 运算符隐式包含强转 (short)(s1 + 1)
  ```
* **强制类型截断与补码计算**：
  ```java
  byte b = (byte) 130; 
  System.out.println(b); // 输出 -126 !
  // 解析：130 的 int 原码为 00000000 00000000 00000000 10000010
  // 强转 byte 截断低 8 位为 10000010（符号位为1，是负数补码）
  // 补码 10000010 -> 反码 10000001 -> 原码 11111110 -> 对应十进制 -126
  ```

---

### 8. 浮点数精度与 `BigDecimal`
* **二进制精度缺失**：`0.1 + 0.2 == 0.3` 在 Java 中返回 **`false`**（IEEE 754 二进制无法精确表示十进制小数 0.1 和 0.2，计算结果为 `0.30000000000000004`）；
* **`BigDecimal` 避坑**：禁止使用 `new BigDecimal(0.1)`（依然存在精度丢失），**必须使用 `new BigDecimal("0.1")` 或 `BigDecimal.valueOf(0.1)`**。

## ☕ 模块二：Java 泛型、异常体系、接口新特性与集合底层考点

### 1. 泛型类型擦除与通配符（PECS 原则）
* **类型擦除**：Java 泛型是伪泛型，编译期会将类型参数擦除为其上限（未指定则擦除为 `Object`）。因此 `List<String>` 和 `List<Integer>` 在运行期的 `getClass()` 完全相同；且无法通过重载定义 `void test(List<String> a)` 和 `void test(List<Integer> b)`。
* **PECS 原则（Producer Extends, Consumer Super）**：
  - **`<? extends T>`（上界通配符）**：只读不写。可以安全地从中读取数据（作为生产者 Producer），但**禁止写入任何元素（除了 `null`）**；
  - **`<? super T>`（下界通配符）**：只写不读。可以安全地向其中写入 `T` 及其子类对象（作为消费者 Consumer），但读取出来的对象只能是 `Object`。

---

### 2. Java 接口新特性与菱形继承冲突
* **Java 8+ 接口方法**：
  - 可以包含 **`default` 默认方法** 和 **`static` 静态方法**；
  - Java 9 甚至允许接口中定义 **`private` 私有方法**（抽取公共代码）。
* **冲突解决规则**：
  1. **类优先原则**：若父类和接口定义了同名同参方法，**子类优先继承父类的方法**；
  2. **接口冲突**：若实现的多个接口中有相同的 `default` 方法，**子类必须显式重写并指定调用哪个接口**（如 `InterfaceA.super.foo()`）。

---

### 3. Java 异常继承体系（Checked vs Unchecked）
```
                       Throwable (顶级父类)
                      /                  \
             Error (严重致命错误)        Exception (程序可捕获异常)
            /        |         \              /             \
    StackOverflow  OOM   VirtualMachineError  /               \
                                    RuntimeException     Checked Exception
                                   (非受检/运行时异常)   (受检异常，编译期强检)
                                   /        |        \          /       |       \
                                 NPE   ClassCast  IndexOut   IOException SqlEx  ClassNotFound
```
* **受检异常（Checked Exception）**：编译期强制要求必须 `try-catch` 或 `throws` 声明（如 `IOException`, `SQLException`, `ClassNotFoundException`）；
* **非受检异常（Unchecked / RuntimeException）**：编译期不强制要求处理，通常由程序代码逻辑错误引起（如 `NullPointerException`, `ClassCastException`, `ArrayIndexOutOfBoundsException`, `ArithmeticException`）。

---

### 4. `HashMap` 核心底层机制与参数
* **默认初始容量**：`16`（必须是 2 的幂次方，便于使用位运算 `(n - 1) & hash` 代替取模运算 `%`）；
* **默认负载因子**：`0.75`（在时间与空间成本间取得泊松分布最佳平衡）；
* **树化阈值**：**链表长度 $\ge 8$ 且 数组总容量 $\ge 64$** 才会转化为红黑树（若容量 $< 64$ 则优先进行数组扩容）；
* **退化阈值**：红黑树节点数在扩容拆分后 $\le 6$ 时退化为普通链表；
* **Key 为 null 的支持**：`HashMap` 允许一个 Key 为 `null`（放在下标 0 位置）；而 `Hashtable` 与 `ConcurrentHashMap` **严格禁止 Key 或 Value 为 null**！

## 🧵 模块三：Java 多线程、锁机制与并发状态机考点

### 1. 线程核心方法横向对比
| 方法名 | 所属类 | 是否释放 CPU | 是否释放锁 | 唤醒/恢复方式 |
| :--- | :--- | :--- | :--- | :--- |
| **`Thread.sleep(ms)`** | `Thread` | **是** | **否（依然持有锁）** | 休眠时间到期自动苏醒 |
| **`Object.wait()`** | `Object` | **是** | **是（立刻释放对象监视器锁）** | 依赖其他线程调用 `notify()` 或 `notifyAll()` |
| **`Thread.yield()`** | `Thread` | **是（转入就绪态）** | **否** | 由 CPU 调度器重新选择线程执行 |
| **`thread.join()`** | `Thread` | **是** | **是（底层调用的 wait）** | 目标线程执行完毕自动唤醒 |

---

### 2. `volatile` 关键字的三大特性
* **保证可见性**：通过 CPU 缓存一致性协议（MESI）与总线嗅探，修改立即刷回主内存并通知其他 CPU 核心本地缓存失效；
* **禁止指令重排**：底层通过插入内存屏障（Load/Store Barrier）防止编译器和 CPU 乱序优化；
* **❌ 不保证原子性**：无法保证类似 `count++` 的复合操作的线程安全（`count++` 包含读、改、写三步字节码）。

---

### 3. 线程池生命周期 5 大状态流转
$$\mathbf{RUNNING} \xrightarrow{\text{shutdown()}} \mathbf{SHUTDOWN} \xrightarrow{\text{队列与任务清空}} \mathbf{TIDYING} \rightarrow \mathbf{TERMINATED}$$
$$\mathbf{RUNNING} \xrightarrow{\text{shutdownNow()}} \mathbf{STOP} \xrightarrow{\text{活动任务终止}} \mathbf{TIDYING} \rightarrow \mathbf{TERMINATED}$$
* `RUNNING`：接受新任务并处理队列任务；
* `SHUTDOWN`：不接受新任务，但继续处理工作队列中已有的任务；
* `STOP`：不接受新任务，不处理队列任务，并中断正在执行的任务；
* `TIDYING`：所有任务已终止，有效线程数为 0；
* `TERMINATED`：`terminated()` 钩子方法执行完毕进入终态。

---

### 4. `synchronized` vs `ReentrantLock` vs 原子类 CAS 核心对比（银行高并发编程题考点）
| 对比维度 | `synchronized` (内置锁) | `ReentrantLock` (显式锁) | 原子类 `AtomicXxx` / CAS (无锁) |
| :--- | :--- | :--- | :--- |
| **底层实现** | JVM 关键字，Monitor 监视器 (`monitorenter/exit`)，依赖 OS Mutex | JUC 类，基于 **AQS 同步队列** 与 `LockSupport.park()/unpark()` | 基于 CPU 硬件指令 **`CAS (CMPXCHG)`**，非阻塞乐观自旋 |
| **高并发性能** | 阻塞锁，导致成千上万线程挂起陷入内核态，**上下文切换开销巨大** | 依然是悲观阻塞锁，支持公平/非公平/超时 `tryLock` | **最高！线程不休眠不阻塞**，在用户态直接自旋重试完成更新 |
| **银行高并发推荐** | ❌ 吞吐量低，容易阻塞 | ❌ 依然有线程挂起开销 | ✅ **极力推荐（`AtomicLong` / `LongAdder`）** |
| **高并发累加首选** | 单 Key 锁竞争激烈 | 单 Key 锁竞争激烈 | **`LongAdder`（分段累加 Cell 数组，吞吐量比 AtomicLong 高一个数量级）** |
| **ABA 问题与解法** | 无 ABA 问题 | 无 ABA 问题 | 存在 ABA 问题，使用 **`AtomicStampedReference`（加版本号）** 解决 |

## 🔢 模块四：经典数据结构 (二叉树/红黑树/B树/哈夫曼) 与图论算法

### 1. 二叉树核心性质与节点计算（笔试单选第 1 高频）
1. **叶子节点与度为 2 的节点定理（核心公式）**：
   $$\mathbf{n_0 = n_2 + 1}$$
   （任何二叉树中，**度为 0 的叶子节点数永远比度为 2 的分支节点数多 1 个**！无论度为 1 的节点有多少个！）
2. **总节点数与边数公式**：
   $$N = n_0 + n_1 + n_2 = \text{总边数} + 1 = (n_1 + 2n_2) + 1$$
3. **二叉树深度与节点最值**：
   - 深度为 $k$ 的二叉树最多有 $\mathbf{2^k - 1}$ 个节点；第 $i$ 层最多有 $\mathbf{2^{i-1}}$ 个节点；
   - 具有 $N$ 个节点的完全二叉树深度为 $\mathbf{\lfloor \log_2 N \rfloor + 1}$ 或 $\mathbf{\lceil \log_2(N + 1) \rceil}$；
   - **完全二叉树父子节点编号关系（根从 1 开始）**：
     - 节点 $i$ 的左孩子为 $2i$（若 $2i > N$ 则无左孩子）；
     - 节点 $i$ 的右孩子为 $2i + 1$（若 $2i + 1 > N$ 则无右孩子）；
     - 节点 $i$ 的双亲节点编号为 $\lfloor i / 2 \rfloor$；
     - 最后一个非叶子节点的编号为 $\mathbf{\lfloor N / 2 \rfloor}$（建堆起点！）。

---

### 2. 二叉树遍历序列还原（笔试必考手工画树题）
* **【铁律】**：
  - **前序遍历（Pre-order）**：`[根] -> [左子树] -> [右子树]`（第一个必是根节点）；
  - **后序遍历（Post-order）**：`[左子树] -> [右子树] -> [根]`（最后一个必是根节点）；
  - **中序遍历（In-order）**：`[左子树] -> [根] -> [右子树]`（根节点在中间，把左右子树切分开！）；
* **【还原判定法则】**：
  - ✅ **前序 + 中序**：可唯一确定一棵二叉树；
  - ✅ **后序 + 中序**：可唯一确定一棵二叉树；
  - ❌ **前序 + 后序**：**绝对无法唯一确定一棵二叉树**（只能确定祖先与子孙关系，无法区分左孩子还是右孩子！）。

---

### 3. 哈夫曼树（Huffman Tree 最优二叉树）与带权路径长度 (WPL)
1. **核心特征**：
   - **度为 1 的节点数严格为 0**（$n_1 = 0$）；
   - 若有 $n$ 个叶子节点，则构造成的哈夫曼树**总节点数必定为 $\mathbf{2n - 1}$ 个**！
2. **构造方法（贪心法）**：每次在权重集合中挑选**两个权值最小**的节点作为左右孩子合并，生成一个新节点（权值为两者之和），重复直至合并为一棵树。
3. **带权路径长度（WPL, Weighted Path Length）**：
   $$WPL = \sum_{i=1}^n w_i \times l_i$$
   （等于所有非叶子节点的权值之和！这个速算技巧比乘路径长度快 5 倍）。
4. **哈夫曼编码**：左分支标 0，右分支标 1，属于**前缀编码（Prefix Code）**，任何字符的编码绝不是其他字符编码的前缀，解码无歧义。

---

### 4. 二叉搜索树 (BST) vs 平衡二叉树 (AVL) vs 红黑树 (RBT)

| 树结构 | 核心定义与平衡性 | 查找/插入/删除时间复杂度 | 旋转开销与适用场景 |
| :--- | :--- | :--- | :--- |
| **二叉搜索树 (BST)** | 左子树所有节点 $<$ 根 $<$ 右子树所有节点；中序遍历结果严格递增。 | 平均 $O(\log N)$；**最坏退化为单链表 $O(N)$**。 | 无平衡机制。 |
| **平衡二叉树 (AVL)** | 任何节点的左右子树**高度差绝对值不超过 1**（平衡因子 $\in \{-1, 0, 1\}$）。 | 严格 $O(\log N)$。 | **旋转频繁**：插入最多 2 次旋转，删除最多 $O(\log N)$ 次旋转。适合**查多写少**场景。 |
| **红黑树 (RBT)** | 自平衡二叉搜索树，通过颜色约束保证**最长路径不超过最短路径的 2 倍**。 | 稳定 $O(\log N)$。 | **旋转开销小**：插入最多 2 次旋转，删除最多 3 次旋转。适合**写多查多**场景（Java `TreeMap`、`HashMap` 链表长度 $\ge 8$ 转红黑树）。 |

#### 💡 红黑树的 5 大强制特性（笔试多选常考）：
1. 每个节点要么是红色，要么是黑色；
2. **根节点必定是黑色**；
3. **所有叶子节点（NIL 空节点）必定是黑色**；
4. **红色节点不能连续**（红色节点的父节点和子节点必须是黑色）；
5. **从任一节点到其所有后代叶子节点的简单路径上，黑色节点的数量相同（黑高 Black-Height 相同）**。

---

### 5. B 树 (B-Tree) vs B+ 树 (B+ Tree) 核心区别（数据库与系统笔试核心）

* **$m$ 阶 B 树（多路平衡查找树）的考点**：
  - 根节点至少有 2 个子节点；
  - 非根非叶子节点至少有 $\lceil m / 2 \rceil$ 个子节点；
  - 节点包含的关键字个数范围：$\mathbf{[\lceil m/2 \rceil - 1, \, m - 1]}$；
  - 节点包含的关键字数比子树指针数**少 1 个**。
* **B+ 树相比 B 树的三大变动（MySQL 选用 B+ 树的原因）**：
  1. **非叶子节点只存索引键，不存数据**（使得单个 16KB 页能容纳更多键，树更矮胖，磁盘 I/O 更少）；
  2. **所有叶子节点包含了全部关键字和数据**，并且**叶子节点之间通过双向链表相连**；
  3. **范围查询极佳**：B 树范围查询需要中序遍历跨层回溯；B+ 树只需在叶子双向链表上顺序向后扫。

### 6. 图的定义、边数计算与存储结构

#### 1. 图的边数与顶点关系公式（选择题必考）：
* **无向完全图（任意两点都有边）**：边数 $E = \mathbf{\frac{n(n-1)}{2}}$；
* **有向完全图（任意两点都有互逆两条弧）**：弧数 $E = \mathbf{n(n-1)}$；
* **无向连通图的极小生成树**：边数最少为 $\mathbf{n - 1}$；若边数 $< n-1$ 则必不连通；
* **强连通有向图**：从任意顶点到任意顶点都有路径，最少弧数为 $\mathbf{n}$（形成一个闭环）；
* **握手定理（度数和与边数）**：**所有顶点的度数之和等于边数的 2 倍**：$$\sum_{i=1}^n \text{deg}(v_i) = 2E$$。

#### 2. 图的两大主流存储结构对比：

| 存储结构 | 存储原理 | 空间复杂度 | 适用场景与优缺点 |
| :--- | :--- | :--- | :--- |
| **邻接矩阵 (Adjacency Matrix)** | 用二维数组 `edges[n][n]` 表示点与点是否有边/权值。对称矩阵可压缩为一维数组。 | $\mathbf{O(V^2)}$（与边数无关） | 适合**稠密图**；判断任意两点是否有边极快 $O(1)$；但在稀疏图下浪费大量内存。 |
| **邻接表 (Adjacency List)** | 顶点用一维数组存储，每个顶点的所有出边挂成一个单链表。 | 无向图：$\mathbf{O(V + 2E)}$<br>有向图：$\mathbf{O(V + E)}$ | 适合**稀疏图**；查找某个顶点的邻居节点极快；但在有向图中求入度需要遍历全表（可用逆邻接表或十字链表）。 |

### 7. 最短路径三大算法全家桶（笔试考原理与时空复杂度）

| 算法名 | 算法核心思想 | 解决问题类型 | 能否处理负权边 | 时间复杂度 |
| :--- | :--- | :--- | :--- | :--- |
| **迪杰斯特拉 (Dijkstra)** | **贪心思想**：每次从未访问节点中选择一个距离源点最近的节点加入已确定集合，并松弛其邻居。 | 单源最短路径（指定起点到其余各点） | ❌ **绝对不能处理负权边**（贪心策略会失效） | 普通版：$\mathbf{O(V^2)}$<br>优先队列/最小堆优化：$\mathbf{O(E \log V)}$ |
| **贝尔曼-福特 (Bellman-Ford) / SPFA** | **动态规划与队列优化**：对所有边进行 $V - 1$ 次松弛操作。 | 单源最短路径 | ✅ **支持负权边，能检测是否存在负权回路** | Bellman-Ford: $O(VE)$<br>SPFA 平均 $O(kE)$ |
| **弗洛伊德 (Floyd-Warshall)** | **动态规划**：三重循环，以每个顶点 $k$ 作为中间跳板更新任意 $i$ 到 $j$ 的最短距离：`d[i][j] = min(d[i][j], d[i][k] + d[k][j])`。 | **多源最短路径（任意两点间）** | ✅ **支持负权边，但不能有负权回路** | $\mathbf{O(V^3)}$，代码极简（三重 for 循环）。 |

---

### 8. 最小生成树 (MST) 两大算法：Prim vs Kruskal

| 算法名 | 算法核心思想 | 适用图类型 | 时间复杂度 | 核心贪心策略 |
| :--- | :--- | :--- | :--- | :--- |
| **普里姆 (Prim) 算法** | **从顶点出发**：从任意顶点开始，每次选择距离“当前已生成的连通树”最近的顶点加入树中。 | **稠密图**（边多的图） | $\mathbf{O(V^2)}$（堆优化后 $O(E \log V)$） | 类似 Dijkstra，逐步将点纳入集合。 |
| **克鲁斯卡尔 (Kruskal) 算法** | **从边出发**：将所有边按权值从小到大排序，每次选取一条权值最小且**不与已有边构成环**的边加入。 | **稀疏图**（边少的图） | $\mathbf{O(E \log E)}$（依赖排序） | 必须配合 **并查集（Disjoint-Set）** 检测是否成环！ |

### 9. 拓扑排序 (Topological Sort) 与关键路径 (AOV / AOE 网)
* **拓扑排序（AOV 网）**：适用于 **有向无环图（DAG）**。入度为 0 的顶点入队输出，删除其所有出边。若最终输出顶点数 $< n$，**说明图中有环（存在死锁）**！
* **关键路径（AOE 网）**：从源点到汇点具有**最大路径长度（总工期最长）**的路径。**关键活动的最早开始时间 $e(i)$ 等于最迟开始时间 $l(i)$**。缩短非关键活动时间无法缩短总工期。

## 📊 模块五：线性结构、栈出栈合法性 (卡特兰数)、循环队列、散列 ASL 计算与 KMP 算法

### 1. 栈进出合法性与卡特兰数 (Catalan Number)
* **出栈序列总数公式（卡特兰数）**：
  $$C_n = \frac{1}{n+1} \binom{2n}{n} = \frac{(2n)!}{(n+1)! \, n!}$$
  - $n = 1 \rightarrow 1$ 种；
  - $n = 2 \rightarrow 2$ 种；
  - $n = 3 \rightarrow \mathbf{5}$ 种；
  - $n = 4 \rightarrow \mathbf{14}$ 种；
  - $n = 5 \rightarrow \mathbf{42}$ 种。
* **【选择题出栈序列合法性秒杀法则】**：
  - **核心铁律**：如果元素 $x$ 已经出栈，那么**在 $x$ 之前进栈但尚未出栈的所有元素，后续出栈的顺序必须严格是逆序的**！
  - *经典例题*：进栈顺序为 $1, 2, 3, 4$，下列哪个出栈序列是不可能的？  
    A. 1, 2, 3, 4 | B. 4, 3, 2, 1 | C. 3, 1, 4, 2 | D. 2, 4, 3, 1  
    👉 **秒杀解析**：选 **C**！若 3 先出栈，说明此时 1 和 2 都在栈内，1 在栈底、2 在栈顶，后续 2 必定先于 1 出栈，不可能出现 1 在 2 之前出栈！

---

### 2. 循环队列四大核心计算公式（队空/队满/队长）
* 为了解决假溢出，采用模运算实现循环队列（数组大小为 `MaxSize`）：
  1. **队头出队移动**：`front = (front + 1) % MaxSize;`
  2. **队尾入队移动**：`rear = (rear + 1) % MaxSize;`
  3. **牺牲一个单元法区分队空与队满（最常考）**：
     - **队空条件**：$\mathbf{front == rear}$；
     - **队满条件**：$\mathbf{(rear + 1) \% MaxSize == front}$；
  4. **当前队列长度（元素个数）公式**：
     $$\mathbf{Queue\_Length = (rear - front + MaxSize) \pmod{MaxSize}}$$
     - *例题*：`MaxSize = 10, front = 8, rear = 3`，当前队长为 $(3 - 8 + 10) \% 10 = \mathbf{5}$。

### 3. 散列表 (Hash Table) 冲突解决与平均查找长度 (ASL) 计算实战

#### 1. 线性探测法 ASL 成功与 ASL 失败手工计算
* **题目背景**：散列表长度 $m = 11$，散列函数 $H(key) = key \pmod 7$，待插入关键字序列为：`{7, 8, 30, 11, 18, 9, 14}`。
* **物理分布计算**：
  - $H(7) = 0 \rightarrow$ 放到位置 0（比较 1 次）；
  - $H(8) = 1 \rightarrow$ 放到位置 1（比较 1 次）；
  - $H(30) = 2 \rightarrow$ 放到位置 2（比较 1 次）；
  - $H(11) = 4 \rightarrow$ 放到位置 4（比较 1 次）；
  - $H(18) = 4 \rightarrow$ 冲突！探测位置 5 空闲，放入（比较 2 次）；
  - $H(9) = 2 \rightarrow$ 冲突！探测位置 3 空闲，放入（比较 2 次）；
  - $H(14) = 0 \rightarrow$ 冲突！探测 1, 2, 3, 4, 5, 6，放入 6（比较 7 次）。
* **【查找成功 ASL】**：
  $$ASL_{\text{成功}} = \frac{\text{所有元素查找次数之和}}{\text{元素总个数}} = \frac{1 + 1 + 1 + 1 + 2 + 2 + 7}{7} = \frac{15}{7} \approx 2.14$$
* **【查找失败 ASL】**：
  - 散列函数余数可能为 $0 \sim 6$ 共 7 种可能。
  - 从余数地址开始向后扫描，直到遇到第一个**空单元格**的比较次数：
    - 地址 0 到空单元格（位置 7）：需比较 8 次；
    - 地址 1 到位置 7：需比较 7 次；
    - 地址 2 到位置 7：需比较 6 次；
    - 地址 3 到位置 7：需比较 5 次；
    - 地址 4 到位置 7：需比较 4 次；
    - 地址 5 到位置 7：需比较 3 次；
    - 地址 6 到位置 7：需比较 2 次；
  $$ASL_{\text{失败}} = \frac{8 + 7 + 6 + 5 + 4 + 3 + 2}{7} = \frac{35}{7} = \mathbf{5}$$

### 4. KMP 模式匹配算法与 `next` 数组快速手算法
* **`next[j]` 的物理含义**：当第 $j$ 个字符失配时，模式串应该回退到的新下标位置（即前 $j-1$ 个字符构成的子串中，**最长相等真前后缀长度 + 1**）。
* **以模式串 `"abaabcac"` 为例（下标从 1 开始）：**
  | 字符序号 $j$ | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
  | :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
  | 字符 $P_j$ | a | b | a | a | b | c | a | c |
  | **`next[j]`** | **0** | **1** | **1** | **2** | **2** | **3** | **1** | **2** |
  - *口诀*：第一位恒为 0，第二位恒为 1；第 $j$ 位看前 $j-1$ 位子串的最长相等前后缀长度，再加 1 即可！

## 🗄️ 模块六：SQL 语法、执行顺序与索引失效场景速查

### 1. SQL 语句的标准底层执行顺序
$$\mathbf{FROM} \rightarrow \mathbf{ON} \rightarrow \mathbf{JOIN} \rightarrow \mathbf{WHERE} \rightarrow \mathbf{GROUP\ BY} \rightarrow \mathbf{HAVING} \rightarrow \mathbf{SELECT} \rightarrow \mathbf{DISTINCT} \rightarrow \mathbf{ORDER\ BY} \rightarrow \mathbf{LIMIT}$$
* **三大高频陷阱**：
  1. `WHERE` 在 `GROUP BY` 前执行，**`WHERE` 后面绝不能跟 `COUNT/SUM/AVG` 聚合函数**（必须写在 `HAVING` 中）；
  2. `SELECT` 在 `WHERE` 之后执行，**`WHERE` 中不能使用 `SELECT` 中定义的别名**；
  3. `ORDER BY` 在 `SELECT` 之后执行，**`ORDER BY` 中可以使用列别名**。

---

### 2. 索引失效 7 大经典场景（口诀：模型数空运最左）
* **模**：前缀模糊查询（`LIKE '%abc'` 失效，`LIKE 'abc%'` 能走索引）；
* **型**：隐式类型转换（字符串字段不加引号 `WHERE phone = 180844` 失效）；
* **数**：在索引列上做运算或函数（`WHERE age + 1 = 18` 或 `WHERE SUBSTR(name,1,2)='张'` 失效）；
* **空**：`IS NOT NULL` 通常走全表；
* **运**：否定运算（`!=`、`<>`、`NOT IN` 范围过大走全表）；
* **最左**：违背最左前缀匹配（联合索引 `(a,b,c)` 查询 `WHERE b=1 AND c=2` 失效）；
* **OR 缺失**：`WHERE a=1 OR d=2`（若 `d` 无索引则全表扫描）。

## 🌐 模块九：计算机网络核心协议、TCP 拥塞控制计算与 IP 子网划分

### 1. TCP 拥塞控制四大算法与动态计算（笔试最爱考计算题）
* **四大算法演进状态机**：
  1. **慢启动（Slow Start）**：`cwnd` 初始为 1（以 MSS 为单位）。每个传输轮次（RTT），`cwnd` **翻倍指数增长**（$1 \rightarrow 2 \rightarrow 4 \rightarrow 8 \dots$）；
  2. **拥塞避免（Congestion Avoidance）**：当 `cwnd >= ssthresh`（慢启动门限）时，转为**加法增大（线性增长，每个 RTT 加 1）**；
  3. **网络超时（Timeout 拥塞发生）**：
     - 新的慢启动门限降为当前窗口的一半：$$\mathbf{ssthresh_{new} = \lfloor cwnd / 2 \rfloor}$$；
     - **拥塞窗口骤降回初始值：$\mathbf{cwnd = 1}$**！重新进入慢启动；
  4. **收到 3 个冗余 ACK（快重传与快恢复）**：
     - 说明只是个别报文丢失，网络并未严重拥塞；
     - $\mathbf{ssthresh_{new} = \lfloor cwnd / 2 \rfloor}$，**但 $\mathbf{cwnd = ssthresh_{new}}$**（不降回 1），直接进入拥塞避免线性递增。

## 💻 模块十：操作系统进程管理、周转时间、页面置换缺页计算与磁盘调度

### 1. 作业/进程调度性能指标计算（周转时间 & 带权周转时间）
* **核心计算公式**：
  1. **周转时间**：$$\text{周转时间} = \text{作业完成时刻} - \text{作业提交到达时刻}$$；
  2. **带权周转时间**（必 $\ge 1$，越小越好）：$$\text{带权周转时间} = \frac{\text{周转时间}}{\text{实际运行服务时间}}$$；
  3. **高响应比优先算法（HRRN）响应比公式**：
     $$R = \frac{\text{等待时间} + \text{服务时间}}{\text{服务时间}} = 1 + \frac{\text{等待时间}}{\text{服务时间}}$$
     （等待越久响应比越高，避免饥饿；作业时间越短响应比越高，兼顾短作业）。

---

### 2. 页面置换算法与缺页中断次数计算实战
* **题目**：系统分配给进程的物理内存块数为 **3**，页面访问引用串为：`7, 0, 1, 2, 0, 3, 0, 4, 2, 3`。
* **三种算法计算对比**：
  - **OPT（最佳置换）**：淘汰**未来最长时间内不再被访问**的页面（理论最优，无法实现，用于衡量其他算法）；
  - **FIFO（先进先出）**：淘汰**最早进入内存**的页面（**唯一可能发生 Belady 异常的算法**，即分配物理块增多缺页次数反而增加）；
  - **LRU（最近最久未使用）**：淘汰**最近最长时间未被访问**的页面（局部性原理最优工程实现）。
* **以 FIFO 为例逐步模拟**：
  - 访问 7 $\rightarrow$ 缺页，装入 `[7]`；
  - 访问 0 $\rightarrow$ 缺页，装入 `[7, 0]`；
  - 访问 1 $\rightarrow$ 缺页，装入 `[7, 0, 1]`；
  - 访问 2 $\rightarrow$ 缺页，淘汰最老的 7，装入 `[2, 0, 1]`；
  - 访问 0 $\rightarrow$ 命中，内存仍为 `[2, 0, 1]`；
  - 访问 3 $\rightarrow$ 缺页，淘汰最老的 0，装入 `[2, 3, 1]`；
  - 访问 0 $\rightarrow$ 缺页，淘汰最老的 1，装入 `[2, 3, 0]`；
  - 访问 4 $\rightarrow$ 缺页，淘汰最老的 2，装入 `[4, 3, 0]`...
  - **总缺页中断次数** = 发生缺页的次数总和；**缺页率** = 缺页次数 / 总访问次数。

## 🎲 模块十一：大厂笔试必考经典智力题与数学概率论

### 1. 25 匹马 5 条赛道找前 3 名（腾讯/字节高频题）
* **问题**：有 25 匹马，只有 5 条赛道，没有计时器，最少比赛几次能找出跑得最快的前 3 名？
* **秒杀答案**：**7 次！**
* **解题推导 3 步走**：
  1. **前 5 次**：将 25 匹马分为 A、B、C、D、E 5 组，各跑一次。假设每组名次排序为 $A_1 > A_2 > A_3 > A_4 > A_5$（其余各组类似）；
  2. **第 6 次（小组第 1 名决赛）**：让 5 组的第 1 名（$A_1, B_1, C_1, D_1, E_1$）跑一次。假设名次为 $A_1 > B_1 > C_1 > D_1 > E_1$。此时**第一名绝对是 $A_1$**！
  3. **淘汰不可能的候选马**：$D$ 组和 $E$ 组全军覆没；$C$ 组只有 $C_1$ 有可能争第 3 名；$B$ 组只有 $B_1, B_2$ 有可能争第 2/3 名；$A$ 组只有 $A_2, A_3$ 有可能争第 2/3 名；
  4. **第 7 次**：让剩下的 5 匹马（$A_2, A_3, B_1, B_2, C_1$）跑最后一次，取前两名分别作为总亚军和总季军！

### 2. 1000 瓶药水 1 瓶有毒，最少需要几只小白鼠（二进制思维）
* **问题**：有 1000 瓶无色无味的药水，其中只有 1 瓶是剧毒的，小白鼠喝了 24 小时后毒发身亡。只有 24 小时时间，最少几只小白鼠能测出哪瓶有毒？
* **秒杀答案**：$$\mathbf{\lceil \log_2 1000 \rceil = 10 \text{ 只！}}$$
* **原理**：每只老鼠只有“死”或“活”两种状态，即 1 个二进制位（Bit）。$N$ 只老鼠能表示 $2^N$ 种状态。因为 $2^9 = 512 < 1000 < 2^{10} = 1024$，所以 10 只老鼠即可对 1000 瓶药水按二进制进行混合喂药定位。

### 3. 贝叶斯概率题：罕见病检测的假阳性陷阱
* **问题**：某种疾病在人群中的患病率为 **0.1%（0.001）**。医院检测准确率为 **99%**（即若有病，99% 概率检出阳性；若没病，99% 概率检出阴性）。某人检测结果为阳性，请问他真正患病的概率是多少？
* **秒杀答案**：**仅约 9%！并不是 99%！**
* **贝叶斯公式推导**：
  - 设人群有 100,000 人：
    - 真正患病人数：$100,000 \times 0.001 = 100$ 人，其中检出阳性 $100 \times 99\% = \mathbf{99}$ 人；
    - 健康人数：$99,900$ 人，其中假阳性（被误诊）人数：$99,900 \times (1 - 99\%) = \mathbf{999}$ 人；
  - 在所有拿到阳性结果的人（$99 + 999 = 1098$ 人）中，真正患病的概率为：
    $$P(\text{真患病} \mid \text{阳性}) = \frac{99}{99 + 999} = \frac{99}{1098} \approx \mathbf{9.01\%}$$

### 4. 100 层高楼扔 2 个鸡蛋测临界摔碎楼层
* **问题**：100 层高楼，手上有 2 个一模一样的鸡蛋。要找出刚好摔碎的临界楼层，在最坏情况下，最少需要尝试扔几次？
* **秒杀答案**：**14 次！**
* **数学原理**：设最坏需要 $x$ 次，为了保证每次尝试失败后步长递减 1，楼层总数满足：
  $$x + (x - 1) + (x - 2) + \dots + 1 = \frac{x(x + 1)}{2} \ge 100$$
  解得最小整数 $x = \mathbf{14}$（第一次在 14 楼扔，若没碎第二次在 $14 + 13 = 27$ 楼扔...）。

### 1. 文件八进制权限与 `chmod` 计算（必考填空/单选）
* **权限位对应数字**：
  - **`r` (Read 读)** = **4**；
  - **`w` (Write 写)** = **2**；
  - **`x` (Execute 执行)** = **1**；
  - `-` (无权限) = **0**。
* **三组权限划分**：`[所有者 User] [所属组 Group] [其他人 Others]`
  - `chmod 755 file` $\rightarrow$ `rwxr-xr-x`（所有者可读写执行 7，所属组与其他只能读与执行 5）；
  - `chmod 644 file` $\rightarrow$ `rw-r--r--`（所有者可读写 6，其他所有人只读 4）；
  - `chmod 777 file` $\rightarrow$ `rwxrwxrwx`（最高权限，所有人可读写执行）。

## ⚡ 终极附录：秋招笔试选择题 70 条一秒破局秒杀口诀

1. **`i = i++`** 结果永远是原值，`i = ++i` 才是增加后的值。
2. **`Integer`** 在 `[-128, 127]` 范围用 `==` 是 `true`，超出是 `false`；包装类与基本类型 `==` 永远拆箱比数值。
3. **`String`** 字面量相加在常量池，带变量相加在堆上 `new StringBuilder`。
4. **`try-finally`** 中，`finally` 里的 `return` 吞掉一切返回值和未捕获异常。
5. **父子类加载顺序**：父类静态 $\rightarrow$ 子类静态 $\rightarrow$ 父类构造 $\rightarrow$ 子类构造。
6. **多态调用**：方法看右边（子类重写），成员变量和静态方法看左边（父类声明）。
7. **重写规则**：两同两小一大，子类访问权限绝不能小于父类，`private` 无法重写。
8. **二叉树叶子公式**：$n_0 = n_2 + 1$，叶子节点永远等于度为 2 的节点数加 1。
9. **完全二叉树编号**：节点 $i$ 的左孩子是 $2i$，右孩子是 $2i+1$，父节点是 $\lfloor i/2 \rfloor$。
10. **二叉树还原**：前序+中序、后序+中序能唯一确定；**前序+后序绝对无法唯一确定**。
11. **哈夫曼树节点数**：$n$ 个叶子节点构造的哈夫曼树总节点数恒为 **$2n - 1$**，度为 1 节点数为 0。
12. **红黑树定义**：根是黑、叶是黑（NIL）、红不连、黑高处处相同；最长路径 $\le 2 \times$ 最短路径。
13. **无向完全图边数**：$\frac{n(n-1)}{2}$，有向完全图弧数：$n(n-1)$。
14. **图的度数与边数**：所有顶点度数之和等于边数的 2 倍（$\sum D = 2E$）。
15. **最短路径选型**：Dijkstra 贪心单源禁负权边；Floyd 动态规划多源 $O(V^3)$ 允许负权边。
16. **最小生成树选型**：稠密图选 Prim（定点操作 $O(V^2)$），稀疏图选 Kruskal（边排序+并查集 $O(E \log E)$）。
17. **拓扑排序**：适用于有向无环图 (DAG)，入度为 0 出队；最终输出数 $< n$ 必有环。
18. **卡特兰数公式**：$C_n = \frac{1}{n+1}\binom{2n}{n}$，3 个元素出栈 5 种，4 个元素出栈 14 种。
19. **出栈合法性**：某元素出栈后，在它之前进栈且未出栈的元素后续必须**逆序出栈**。
20. **循环队列队长**：$(rear - front + MaxSize) \% MaxSize$；队满条件：$(rear + 1) \% MaxSize == front$。
21. **排序稳定性口诀**：**快选堆希不稳定**（快速排序、简单选择、堆排、希尔不稳定，其余稳定）。
22. **快排最坏时间**：当输入数据基本有序时，退化为 $O(N^2)$。
23. **SQL 执行顺序**：`FROM` 最先跑，`WHERE` 在分组前，`HAVING` 在分组后，`ORDER BY` 倒数第二，`LIMIT` 最后。
