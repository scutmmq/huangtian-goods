## 🎯 模块一：Java 基础核心与代码输出陷阱题（必考 10 大坑点）

### 坑点 1：类初始化与继承执行顺序（笔试代码输出第 1 高频）
* **【绝对公式】**：
  $$\text{父类静态（代码块/变量）} \rightarrow \text{子类静态} \rightarrow \text{父类实例代码块/成员变量} \rightarrow \text{父类构造器} \rightarrow \text{子类实例代码块/成员变量} \rightarrow \text{子类构造器}$$
* **【避坑死穴】**：
  1. **静态代码块只在类第一次被加载时执行 1 次**；后续再 `new` 多个对象时，静态块绝不再执行！
  2. **多态下的属性 vs 方法**：
     - **普通成员方法**：看右边（动态绑定，执行子类重写的方法）；
     - **成员变量（字段）与静态方法**：**看左边（编译期静态绑定，直接取声明类/父类的值）**！

```java
// 经典真题示例：
class Father {
    int num = 10;
    static { System.out.print("1 "); }
    { System.out.print("2 "); }
    public Father() { System.out.print("3 "); }
    public void show() { System.out.print("F "); }
}
class Son extends Father {
    int num = 20;
    static { System.out.print("4 "); }
    { System.out.print("5 "); }
    public Son() { System.out.print("6 "); }
    public void show() { System.out.print("S "); }
}
// 执行：Father obj = new Son(); System.out.print(obj.num + " "); obj.show();
// 输出：1 4 2 3 5 6 10 S (注意：obj.num 取父类的 10，obj.show() 调子类的 show)
```

### 坑点 2：`try-catch-finally-return` 执行顺序与返回值
* **【四条铁律】**：
  1. **`finally` 里的 `return` 会彻底覆盖** `try` 和 `catch` 中的任何返回值或未抛出的异常；
  2. **基本数据类型**：`try` 中的 `return i;` 会先把 `i` 的值复制一份暂存在操作数栈底，即便 `finally` 中执行了 `i++`，**也不会改变返回的值**！
  3. **引用类型对象**：`try` 中 `return sb;` 暂存的是对象的内存地址引用，如果 `finally` 中修改了 `sb.append("b")`，**返回值的内容会发生改变**！
  4. 只有在执行 `System.exit(0)` 或 JVM 崩溃时，`finally` 才不会被执行。

```java
// 经典真题：
public static int test() {
    int i = 1;
    try {
        return i; // 暂存返回值 1
    } finally {
        i++;      // 修改局部变量 i=2，但不影响已暂存的返回值
    }
} // 返回值是 1

public static StringBuilder testRef() {
    StringBuilder sb = new StringBuilder("A");
    try {
        return sb; // 暂存 sb 引用地址
    } finally {
        sb.append("B"); // 修改同一块堆内存
    }
} // 返回的 StringBuilder 内容是 "AB"
```

### 坑点 3：`String` 字符串常量池与比较 (`==` vs `equals`)
* **【核心规则】**：
  1. **字面量拼接（常量折叠）**：`String s = "a" + "b";` 编译期直接优化为 `"ab"`，指向常量池；
  2. **含变量的拼接**：`String s1 = "a"; String s2 = s1 + "b";` 运行期底层通过 `new StringBuilder().append().toString()` 实现，**在堆上产生新对象**！
  3. `new String("abc")` 创建了几个对象？
     - 若常量池中已有 `"abc"`，则只在堆上创建 **1 个** 对象；
     - 若常量池中没有 `"abc"`，则在常量池和堆上各创建 1 个，共 **2 个** 对象。
  4. `s.intern()`：返回常量池中对应的引用。

```java
String s1 = "hello";
String s2 = "he" + "llo";           // 常量折叠，指向常量池同一个地址
String s3 = new String("hello");     // 堆中新对象
String s4 = "he";
String s5 = s4 + "llo";             // 运行期 new StringBuilder，堆中新对象

System.out.println(s1 == s2); // true
System.out.println(s1 == s3); // false
System.out.println(s1 == s5); // false
System.out.println(s1 == s5.intern()); // true (intern 返回常量池引用)
```

### 坑点 4：包装类缓存池（Integer Cache `-128 ~ 127`）
* **【缓存范围清单】**：
  - `Byte`, `Short`, `Integer`, `Long`：缓存 **`[-128, 127]`**；
  - `Character`：缓存 **`[0, 127]`**；
  - `Boolean`：缓存 `TRUE`, `FALSE`；
  - `Float`, `Double`：**完全没有缓存**（每次赋值都是新对象）！
* **【自动拆箱机制】**：
  - 包装类与包装类 `==` 比较的是 **对象内存地址**；
  - 包装类与基本类型 `==` 比较时，**会自动拆箱为数值比较**！

```java
Integer a = 127, b = 127;
System.out.println(a == b); // true (命中缓存池对象)

Integer c = 128, d = 128;
System.out.println(c == d); // false (超出 127，分别 new 了新对象)

int e = 128;
System.out.println(c == e); // true (有基本类型参与，自动拆箱为 int 数值比较)
```

### 坑点 5：自增自减运算顺序 (`i++` vs `++i`)
* **【JVM 栈执行本质】**：
  - `i++`：先将 `i` 的原值压入操作数栈，然后局部变量表里的 `i` 自增 +1；
  - `++i`：局部变量表里的 `i` 先自增 +1，然后把加完后的新值压入操作数栈。

```java
// 经典绝杀题：
int i = 0;
i = i++; 
System.out.println(i); // 输出 0 !
// 解析：① 将 i=0 压栈；② i 自增为 1；③ 将栈顶的 0 弹出赋值给 i，i 被覆盖回 0。

int a = 1;
int b = a++ + ++a * a++; // a 变化轨迹: a++(用1,变2) + ++a(变3,用3) * a++(用3,变4)
// 计算: 1 + 3 * 3 = 10
```

### 坑点 6：方法重写（Override）与重载（Overload）规则
* **方法重载（Overload）**：同一类中，**方法名必须相同，参数列表必须不同**（类型/个数/顺序）。与返回值类型、访问修饰符**完全无关**！
* **方法重写（Override）口诀：两同两小一大**：
  - **两同**：方法名相同、参数列表相同；
  - **两小**：子类返回值类型 $\le$ 父类返回值类型；子类抛出异常类型 $\le$ 父类抛出异常类型；
  - **一大**：**子类访问权限修饰符 $\ge$ 父类**（如父类是 `protected`，子类只能是 `protected` 或 `public`；`private` 方法不能被重写）。

### 坑点 7：集合遍历修改异常 `ConcurrentModificationException`
* **【避坑】**：在 `for-each` 或普通 `Iterator` 遍历集合时，如果调用了 `list.remove()` 或 `list.add()`，会导致 `modCount != expectedModCount`，立即抛出 `ConcurrentModificationException`。
* **【正解】**：必须使用迭代器自带的 `iterator.remove()`，或者 Java 8 的 `list.removeIf(...)`。

## 🔢 模块二：循环次数、树结构与算法复杂度速算公式

### 1. 常见循环次数与时间复杂度速算
| 循环代码结构 | 循环执行次数 | 时间复杂度 |
| :--- | :--- | :--- |
| `for (int i = 0; i < n; i++)` | $n$ | $O(n)$ |
| `for (int i = 1; i < n; i *= 2)` | $\lceil \log_2 n \rceil$ | $O(\log n)$ |
| `for (int i = 0; i < n; i++) for (int j = 0; j < i; j++)` | $\frac{n(n-1)}{2}$ | $O(n^2)$ |
| `for (int i = 1; i <= n; i++) for (int j = 1; j <= n; j *= 2)` | $n \lceil \log_2 n \rceil$ | $O(n \log n)$ |
| `for (int i = n; i > 0; i /= 2) for (int j = 0; j < i; j++)` | $n + \frac{n}{2} + \frac{n}{4} + \dots \approx 2n$ | $O(n)$ |

### 2. 二叉树必备计算公式（笔试单选题必考）

1. **叶子节点与双分支节点关系定理（宇宙第一公式）**：
   $$\mathbf{n_0 = n_2 + 1}$$
   - *含义*：任何一棵二叉树中，**度为 0 的叶子节点数（$n_0$）永远等于度为 2 的节点数（$n_2$）加 1**！（与度为 1 的节点数 $n_1$ 毫无关系）。
   - *总节点数*：$N = n_0 + n_1 + n_2$。
   - *总边数（度数）*：$E = N - 1 = n_1 + 2n_2$。

2. **树高度与节点数最值**：
   - 深度为 $k$ 的二叉树，**最多**有 $2^k - 1$ 个节点（满二叉树）；第 $i$ 层最多有 $2^{i-1}$ 个节点；
   - 具有 $N$ 个节点的完全二叉树，其深度为 $\mathbf{\lfloor \log_2 N \rfloor + 1}$。

3. **完全二叉树父子节点编号索引（从 1 开始标号）**：
   - 节点 $i$ 的左孩子编号为：$\mathbf{2i}$（若 $2i > N$ 则无左孩子）；
   - 节点 $i$ 的右孩子编号为：$\mathbf{2i + 1}$（若 $2i+1 > N$ 则无右孩子）；
   - 节点 $i$ 的双亲节点编号为：$\mathbf{\lfloor i / 2 \rfloor}$；
   - 最后一个非叶子节点的编号为：$\mathbf{\lfloor N / 2 \rfloor}$。

## 🗄️ 模块三：SQL 笔试核心考点与索引失效场景速查

### 1. SQL 语句的标准底层执行顺序
$$\mathbf{FROM} \rightarrow \mathbf{ON} \rightarrow \mathbf{JOIN} \rightarrow \mathbf{WHERE} \rightarrow \mathbf{GROUP\ BY} \rightarrow \mathbf{HAVING} \rightarrow \mathbf{SELECT} \rightarrow \mathbf{DISTINCT} \rightarrow \mathbf{ORDER\ BY} \rightarrow \mathbf{LIMIT}$$

* **【三大高频陷阱】**：
  1. `WHERE` 执行在 `GROUP BY` 之前，所以 **`WHERE` 后面绝对不能使用聚合函数**（如 `WHERE COUNT(*) > 1` 报语法错误！必须写在 `HAVING` 中）；
  2. `SELECT` 在 `WHERE` 之后执行，所以 **`WHERE` 中不能使用 `SELECT` 定义的列别名**；
  3. `ORDER BY` 在 `SELECT` 之后执行，所以 **`ORDER BY` 中可以使用列别名**。

---

### 2. 索引失效 7 大经典场景（口诀：模型数空运最左）
| 失效场景 | 错误 SQL 示例 | 为什么失效与正解 |
| :--- | :--- | :--- |
| **模**（模糊查询前缀 `%`） | `WHERE name LIKE '%三'` | 以 `%` 开头无法走 B+Tree 顺序扫描（正解：`LIKE '张%'` 能走索引）。 |
| **型**（隐式类型转换） | `WHERE phone = 180844`（phone 为 varchar） | 字段类型不一致会触发 MySQL 内部 `CAST()` 函数导致全表扫描（正解：加单引号 `'180844'`）。 |
| **数**（索引列上用函数/运算） | `WHERE SUBSTR(name,1,2)='张'` 或 `WHERE age + 1 = 18` | 对索引列做运算无法利用有序 B+Tree（正解：`WHERE age = 17`）。 |
| **空**（不恰当的判空） | `WHERE age IS NOT NULL` | `IS NOT NULL` 命中数据过多时优化器会放弃索引走全表扫描。 |
| **运**（范围过大的否定运算） | `WHERE age != 18` 或 `NOT IN` | 否定运算通常无法使用索引。 |
| **最左**（违背最左匹配原则） | 联合索引 `(a, b, c)`，执行 `WHERE b = 1 AND c = 2` | 缺少最左引导列 `a`，联合索引完全无法生效。 |
| **OR 条件缺失索引** | `WHERE a = 1 OR d = 2`（d 无索引） | 只要 OR 连接的其中一列没有索引，整个查询全部放弃索引走全表。 |

---

### 3. NULL 值的特殊运算陷阱
1. **比较陷阱**：在 SQL 中，`NULL = NULL` 的结果是 **`UNKNOWN`（假）**，判断空值必须使用 `IS NULL` 或 `IS NOT NULL`；
2. **聚合统计陷阱**：
   - `COUNT(*)` 和 `COUNT(1)` 会统计所有行（**包含 NULL 行**）；
   - `COUNT(column_name)` **会自动过滤掉该字段为 NULL 的行**！
   - `SUM()`, `AVG()`, `MIN()`, `MAX()` 都会自动忽略 NULL 值。

## ☕ 模块四：JVM 内存模型与对象生命周期选择题考点

### 1. 各种变量在 JVM 中的存放位置
| 变量类型 | 代码示例 | 存放内存区域 | 线程安全性 |
| :--- | :--- | :--- | :--- |
| **局部变量（基本类型）** | `int a = 10;`（方法内） | **虚拟机栈帧中的局部变量表** | 线程私有（绝对安全） |
| **局部变量（引用类型）** | `User u = new User();`（方法内） | 引用 `u` 在**栈**上，实际对象在**堆**中 | 引用本身安全，对象看是否逃逸 |
| **实例成员变量** | `class A { int age = 18; }` | **堆**（随对象实例一同存放在堆中） | 线程共享（多线程需加锁） |
| **静态变量（`static`）** | `static int count = 0;` | **堆 / 方法区**（JDK 8 存放在堆中的 Class 对象末尾） | 线程共享 |
| **字符串字面量** | `String s = "abc";` | **堆中的字符串常量池（String Pool）** | 线程共享，全局唯一 |

---

### 2. JVM GC 与参数选择题必背数据
* **分代比例**：默认 `新生代 : 老年代 = 1 : 2`（新生代占 1/3，老年代占 2/3）；
* **新生代内部比例**：`Eden : From Survivor(S0) : To Survivor(S1) = 8 : 1 : 1`；
* **晋升老年代默认年龄**：**15 岁**（Mark Word 中只有 4 个 bit 记录分代年龄，最大 $2^4 - 1 = 15$）；
* **三大 GC 区别**：
  - `Minor GC / Young GC`：只清理新生代（Eden 满时触发）；
  - `Major GC`：只清理老年代（通常只有 CMS 会有纯粹的 Major GC）；
  - `Full GC`：清理整堆（新生代 + 老年代 + 元空间，耗时最长，STW 停顿大）。

## 🌐 模块五：计算机网络与操作系统选择题常考计算与协议

### 1. IP 子网划分与可用主机数计算（笔试常考数学题）
* **【标准计算公式】**：
  - 给定 CIDR 格式 IP：`192.168.1.130/26`
  - **网络号位数**：`26` 位；**主机号位数**：$32 - 26 = 6$ 位；
  - **子网掩码**：前 26 位为 1，即 `255.255.255.192`（$128 + 64 = 192$）；
  - **每个子网总 IP 数**：$2^6 = 64$ 个；
  - **每个子网可用主机数**：$2^6 - 2 = 62$ 个（**必须减去 2 个特殊 IP**：全 0 的网络地址和全 1 的广播地址）；
  - **子网划分区间**：`192.168.1.128 ~ 192.168.1.191`，其中网络号是 `192.168.1.128`，广播地址是 `192.168.1.191`。

### 2. HTTP 核心状态码速查
* **`200 OK`**：请求成功；`204 No Content`：成功但响应无实体；
* **`301 Moved Permanently`**：永久重定向（浏览器会缓存）；
* **`302 Found`**：临时重定向；
* **`304 Not Modified`**：资源未修改（命中协商缓存 ETag / Last-Modified）；
* **`400 Bad Request`**：客户端请求参数语法错误；
* **`401 Unauthorized`**：请求要求身份验证（未登录）；
* **`403 Forbidden`**：服务器拒绝访问（登录了但没有该权限）；
* **`404 Not Found`**：路径不存在；
* **`500 Internal Server Error`**：服务端代码抛出未捕获异常；
* **`502 Bad Gateway`**：网关/反向代理（如 Nginx）无法连接到上游后端服务；
* **`504 Gateway Timeout`**：网关等待上游后端响应超时。

---

### 3. 操作系统页面置换与进程状态转换
* **进程三态转换**：
  - **就绪 $\rightarrow$ 运行**：获得 CPU 时间片；
  - **运行 $\rightarrow$ 就绪**：时间片用完或被更高优先级抢占；
  - **运行 $\rightarrow$ 阻塞**：等待 I/O 事件、等待锁；
  - **阻塞 $\rightarrow$ 就绪**：I/O 完成、获得锁（**注意：阻塞态绝不能直接变成运行态！必须先进入就绪态等待调度**）。
* **四大页面置换算法**：
  - `OPT`（最佳置换）：淘汰未来最长时间不使用的页（理想算法，无法实现）；
  - `FIFO`（先进先出）：可能产生 **Belady 异常**（分配物理块数增多反而缺页次数增加）；
  - `LRU`（最近最久未使用）：基于时间局部性，淘汰最近最长时间未访问的页；
  - `LFU`（最不经常使用）：基于访问频次，淘汰一段时间内访问次数最少的页。

## ⚡ 模块六：秋招笔试选择题 30 条一秒破局避坑口诀

1. **`i = i++`** 结果永远是原值，`i = ++i` 才是增加后的值。
2. **`Integer`** 在 `[-128, 127]` 范围用 `==` 是 `true`，超出是 `false`；包装类与基本类型 `==` 永远拆箱比数值。
3. **`String`** 字面量相加在常量池，带变量相加在堆上 `new StringBuilder`。
4. **`try-finally`** 中，`finally` 里的 `return` 吞掉一切返回值和异常。
5. **父子类加载顺序**：父类静态 $\rightarrow$ 子类静态 $\rightarrow$ 父类构造 $\rightarrow$ 子类构造。
6. **多态调用**：方法看右边（子类），成员变量和静态方法看左边（父类）。
7. **重写规则**：两同两小一大，子类访问权限绝不能小于父类，`private` 无法重写。
8. **二叉树叶子公式**：$n_0 = n_2 + 1$，叶子节点永远等于度为 2 的节点数加 1。
9. **完全二叉树编号**：节点 $i$ 的左孩子是 $2i$，右孩子是 $2i+1$，父节点是 $\lfloor i/2 \rfloor$。
10. **循环对数复杂度**：步长乘除（`i *= 2`）是对数阶 $O(\log n)$，嵌套求和是等差数列 $O(n^2)$。
11. **SQL 执行顺序**：`FROM` 最先跑，`WHERE` 在分组前，`HAVING` 在分组后，`ORDER BY` 倒数第二，`LIMIT` 最后。
12. **`WHERE` 陷阱**：`WHERE` 后面绝对不能加 `COUNT/SUM` 聚合函数。
13. **索引失效**：前导模糊（`%abc`）、隐式转换（数字没加引号）、列上计算（`age+1`）全部失效。
14. **联合索引**：必须满足最左匹配，跳过第一个字段则全失效。
15. **SQL 的 `NULL`**：`NULL = NULL` 是假，`COUNT(*)` 算 NULL，`COUNT(列)` 忽略 NULL。
16. **JVM 变量位置**：局部变量在栈，对象和成员变量在堆，静态变量在堆/方法区。
17. **分代年龄最大值**：15 岁（Mark Word 占 4 个 bit）。
18. **堆新生代比例**：`Eden:S0:S1 = 8:1:1`，新生代占整堆 1/3。
19. **子网计算**：可用主机数一定要减 2（扣除网络地址和广播地址）。
20. **HTTP 304** 是协商缓存未修改，**301** 是永久重定向，**302** 是临时重定向。
21. **HTTP 502** 是网关连不上后端，**504** 是网关等后端超时。
22. **进程状态流转**：阻塞态绝对不能直接变运行态，必须先回就绪态。
23. **页面置换 Belady 异常**：只有 FIFO 算法会出现物理页增多缺页反而增加的现象。
24. **`HashMap` 树化条件**：链表长度 $\ge 8$ 且数组总容量 $\ge 64$。
25. **`HashMap` 初始容量**：总是扩充为 2 的幂次方（为了用 `hash & (n-1)` 代替取模运算 `%`）。
26. **线程启动**：调用 `start()` 启动新线程，直接调用 `run()` 只是主线程普通方法调用。
27. **`volatile` 两大作用**：保证可见性、禁止指令重排，但**不保证原子性**（无法解决 `count++` 线程安全）。
28. **死锁破坏**：破坏请求与保持（一次性申请）、破坏循环等待（按固定递增顺序拿锁）。
29. **排序算法稳定性**：快排、选择、堆排、希尔**不稳定**；冒泡、插入、归并**稳定**（口诀：快选堆希不稳定）。
30. **快排最坏时间复杂度**：当输入数组完全有序时，基准划分极度不平衡，退化为 $O(n^2)$。
