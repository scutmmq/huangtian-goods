## 🎯 模块一：Java 基础语法与代码输出陷阱（必考 8 大题型）

### 1. 类初始化与继承执行顺序（代码输出题第 1 高频）
* **【绝对执行公式】**：
  $$\text{父类静态（块/变量）} \rightarrow \text{子类静态} \rightarrow \text{父类实例代码块/成员变量} \rightarrow \text{父类构造器} \rightarrow \text{子类实例代码块/成员变量} \rightarrow \text{子类构造器}$$
* **【两大必考避坑点】**：
  1. **静态块只在类加载时执行 1 次**，后续 `new` 多个对象时绝不再执行；
  2. **多态调用**：**普通成员方法看右边（动态绑定执行子类重写方法）；成员变量与静态方法看左边（编译期静态绑定，取声明类/父类的值）**！

---

### 2. `try-catch-finally-return` 执行流与返回值
* **规则 1**：`finally` 块中的 `return` 会**彻底覆盖** `try` 和 `catch` 中的任何返回值与未捕获异常；
* **规则 2（基本类型）**：`try { return i; }` 在执行前会将 `i` 的值复制暂存在操作数栈底，即便 `finally { i++; }`，**最终返回值依然不变**；
* **规则 3（引用类型）**：`try { return sb; }` 暂存的是堆内存引用地址，若 `finally { sb.append("B"); }`，**返回值的内容会改变**；
* **规则 4**：只有 `System.exit(0)` 或 JVM 崩溃时，`finally` 才不会执行。

---

### 3. 自增自减陷阱（`i = i++`）
* **经典绝杀题**：
  ```java
  int i = 0;
  i = i++; 
  System.out.println(i); // 输出 0 !
  ```
* **JVM 底层原理**：先将 `i` 的初始值 0 压入操作数栈，然后局部变量表中的 `i` 自增变为 1，最后将操作数栈顶的 0 弹出赋值给 `i`，导致自增后的 1 被覆盖回 0。

---

### 4. 包装类缓存机制与自动拆装箱
* **缓存区间清单**：
  - `Byte`, `Short`, `Integer`, `Long`：缓存 **`[-128, 127]`**；
  - `Character`：缓存 **`[0, 127]`**；
  - `Boolean`：缓存 `TRUE, FALSE`；
  - `Float`, `Double`：**完全没有缓存**（每次赋值都 `new` 新对象）。
* **自动拆箱规则**：两个包装类用 `==` 比较的是对象地址；**只要有基本数据类型参与 `==` 比较，必定自动拆箱为数值比较**。

---

### 5. `String` 常量池与拼接规则
* **常量折叠**：`String s = "a" + "b";` 编译期直接优化为 `"ab"`，指向常量池；
* **含变量拼接**：`String s1 = "a"; String s2 = s1 + "b";` 运行期通过 `StringBuilder` 拼接，**在堆上生成新对象**；
* **`new String("abc")` 对象数**：常量池若已有 `"abc"` 则只在堆上创建 **1 个**；若没有则在常量池和堆上各创建 1 个（共 **2 个**）；
* **`s.intern()`**：返回字符串常量池中的引用。

---

### 6. 位运算与移位操作（`>>` vs `>>>` vs `<<`）
* **`<<`（左移）**：二进制全部左移，低位补 0，相当于乘以 $2^n$；
* **`>>`（算术右移）**：高位补**符号位**（正数补 0，负数补 1），相当于除以 $2^n$；
* **`>>>`（无符号右移）**：无论正负，**高位一律补 0**（负数无符号右移会变成极大的正数）。

---

### 7. 数据类型转换与溢出截断
* **类型自动提升**：`byte, short, char` 在进行算术运算时，一律先自动提升为 **`int`** 再计算！
  ```java
  short s1 = 1;
  s1 = s1 + 1; // ❌ 编译报错！s1 + 1 变成了 int，赋给 short 需要强转
  s1 += 1;     // ✅ 编译通过！+= 运算符隐式包含强转 (short)(s1 + 1)
  ```
* **强制类型截断与补码计算**：
  ```java
  byte b = (byte) 130; 
  System.out.println(b); // 输出 -126 !
  // 解析：130 的 int 原码为 00000000 00000000 00000000 10000010
  // 强转 byte 截断低 8 位为 10000010（符号位为1，是负数补码）
  // 补码 10000010 -> 反码 10000001 -> 原码 11111110 -> 对应十进制 -126
  ```

---

### 8. 浮点数精度与 `BigDecimal`
* **二进制精度缺失**：`0.1 + 0.2 == 0.3` 在 Java 中返回 **`false`**（IEEE 754 二进制无法精确表示十进制小数 0.1 和 0.2，计算结果为 `0.30000000000000004`）；
* **`BigDecimal` 避坑**：禁止使用 `new BigDecimal(0.1)`（依然存在精度丢失），**必须使用 `new BigDecimal("0.1")` 或 `BigDecimal.valueOf(0.1)`**。

## ☕ 模块二：Java 泛型、异常体系与集合底层选择题考点

### 1. 泛型类型擦除与通配符（PECS 原则）
* **类型擦除**：Java 泛型是伪泛型，编译期会将类型参数擦除为其上限（未指定则擦除为 `Object`）。因此 `List<String>` 和 `List<Integer>` 在运行期的 `getClass()` 完全相同。
* **PECS 原则（Producer Extends, Consumer Super）**：
  - **`<? extends T>`（上界通配符）**：只读不写。可以安全地从中读取数据（作为生产者 Producer），但**禁止写入任何元素（除了 `null`）**；
  - **`<? super T>`（下界通配符）**：只写不读。可以安全地向其中写入 `T` 及其子类对象（作为消费者 Consumer），但读取出来的对象只能是 `Object`。

---

### 2. Java 异常继承体系（Checked vs Unchecked）
```
                       Throwable (顶级接口)
                      /                  \
             Error (不可恢复严重错误)    Exception (程序可处理异常)
            /        |         \              /             \
    StackOverflow  OOM   VirtualMachineError  /               \
                                    RuntimeException     Checked Exception
                                   (非受检/运行时异常)   (受检异常，编译期强检)
                                  /        |        \          /       |       \
                                NPE   ClassCast  IndexOut   IOException SqlEx  ClassNotFound
```
* **受检异常（Checked Exception）**：编译期强制要求必须 `try-catch` 或 `throws` 声明（如 `IOException`, `SQLException`, `ClassNotFoundException`）；
* **非受检异常（Unchecked / RuntimeException）**：编译期不强制要求处理，通常由程序代码逻辑错误引起（如 `NullPointerException`, `ClassCastException`, `ArrayIndexOutOfBoundsException`, `ArithmeticException`）。

---

### 3. `HashMap` 核心底层机制与参数
* **默认初始容量**：`16`（必须是 2 的幂次方，便于使用位运算 `(n - 1) & hash` 代替取模运算 `%`）；
* **默认负载因子**：`0.75`（在时间与空间成本间取得泊松分布最佳平衡）；
* **树化阈值**：**链表长度 $\ge 8$ 且 数组总容量 $\ge 64$** 才会转化为红黑树（若容量 $< 64$ 则优先进行数组扩容）；
* **退化阈值**：红黑树节点数在扩容拆分后 $\le 6$ 时退化为普通链表；
* **Key 为 null 的支持**：`HashMap` 允许一个 Key 为 `null`（放在下标 0 位置）；而 `Hashtable` 与 `ConcurrentHashMap` **严格禁止 Key 或 Value 为 null**！

## 🧵 模块三：Java 多线程、锁机制与并发状态机考点

### 1. 线程核心方法横向对比
| 方法名 | 所属类 | 是否释放 CPU | 是否释放锁 | 唤醒/恢复方式 |
| :--- | :--- | :--- | :--- | :--- |
| **`Thread.sleep(ms)`** | `Thread` | **是** | **否（依然持有锁）** | 休眠时间到期自动苏醒 |
| **`Object.wait()`** | `Object` | **是** | **是（立刻释放对象监视器锁）** | 依赖其他线程调用 `notify()` 或 `notifyAll()` |
| **`Thread.yield()`** | `Thread` | **是（转入就绪态）** | **否** | 由 CPU 调度器重新选择线程执行 |
| **`thread.join()`** | `Thread` | **是** | **是（底层调用的 wait）** | 目标线程执行完毕自动唤醒 |

---

### 2. `volatile` 关键字的三大特性
* **保证可见性**：通过 CPU 缓存一致性协议（MESI）与总线嗅探，修改立即刷回主内存并通知其他 CPU 核心本地缓存失效；
* **禁止指令重排**：底层通过插入内存屏障（Load/Store Barrier）防止编译器和 CPU 乱序优化；
* **❌ 不保证原子性**：无法保证类似 `count++` 的复合操作的线程安全（`count++` 包含读、改、写三步字节码）。

---

### 3. 线程池生命周期 5 大状态流转
$$\mathbf{RUNNING} \xrightarrow{\text{shutdown()}} \mathbf{SHUTDOWN} \xrightarrow{\text{队列与任务清空}} \mathbf{TIDYING} \rightarrow \mathbf{TERMINATED}$$
$$\mathbf{RUNNING} \xrightarrow{\text{shutdownNow()}} \mathbf{STOP} \xrightarrow{\text{活动任务终止}} \mathbf{TIDYING} \rightarrow \mathbf{TERMINATED}$$
* `RUNNING`：接受新任务并处理队列任务；
* `SHUTDOWN`：不接受新任务，但继续处理工作队列中已有的任务；
* `STOP`：不接受新任务，不处理队列任务，并中断正在执行的任务；
* `TIDYING`：所有任务已终止，有效线程数为 0；
* `TERMINATED`：`terminated()` 钩子方法执行完毕进入终态。

---

### 4. `synchronized` vs `ReentrantLock` vs 原子类 CAS 核心对比（银行高并发编程题考点）
| 对比维度 | `synchronized` (内置锁) | `ReentrantLock` (显式锁) | 原子类 `AtomicXxx` / CAS (无锁) |
| :--- | :--- | :--- | :--- |
| **底层实现** | JVM 关键字，Monitor 监视器 (`monitorenter/exit`)，依赖 OS Mutex | JUC 类，基于 **AQS 同步队列** 与 `LockSupport.park()/unpark()` | 基于 CPU 硬件指令 **`CAS (CMPXCHG)`**，非阻塞乐观自旋 |
| **高并发性能** | 阻塞锁，导致成千上万线程挂起陷入内核态，**上下文切换开销巨大** | 依然是悲观阻塞锁，支持公平/非公平/超时 `tryLock` | **最高！线程不休眠不阻塞**，在用户态直接自旋重试完成更新 |
| **银行高并发推荐** | ❌ 吞吐量低，容易阻塞 | ❌ 依然有线程挂起开销 | ✅ **极力推荐（`AtomicLong` / `LongAdder`）** |
| **高并发累加首选** | 单 Key 锁竞争激烈 | 单 Key 锁竞争激烈 | **`LongAdder`（分段累加 Cell 数组，吞吐量比 AtomicLong 高一个数量级）** |
| **ABA 问题与解法** | 无 ABA 问题 | 无 ABA 问题 | 存在 ABA 问题，使用 **`AtomicStampedReference`（加版本号）** 解决 |

## 🔢 模块四：树、图结构与核心数学计算公式（笔试必考计算题）

### 1. 二叉树节点关系计算（笔试常考单选题）
1. **叶子节点与度为 2 的节点定理（核心公式）**：
   $$\mathbf{n_0 = n_2 + 1}$$
   （任何二叉树中，**度为 0 的叶子节点数永远比度为 2 的分支节点数多 1 个**！）
2. **总节点数公式**：
   $$N = n_0 + n_1 + n_2 = \text{总边数} + 1 = (n_1 + 2n_2) + 1$$
3. **二叉树深度与节点最值**：
   - 深度为 $k$ 的二叉树最多有 $\mathbf{2^k - 1}$ 个节点；第 $i$ 层最多有 $\mathbf{2^{i-1}}$ 个节点；
   - 具有 $N$ 个节点的完全二叉树深度为 $\mathbf{\lfloor \log_2 N \rfloor + 1}$。

---

### 2. 图论顶点与边数最值计算
1. **无向图边数**：
   - 含有 $n$ 个顶点的无向完全图，边数为：$\mathbf{\frac{n(n-1)}{2}}$；
   - 含有 $n$ 个顶点的无向连通图，最少边数为：$\mathbf{n - 1}$（即生成树）。
2. **有向图边数**：
   - 含有 $n$ 个顶点的有向完全图，弧数为：$\mathbf{n(n-1)}$；
   - 含有 $n$ 个顶点的强连通有向图，最少弧数为：$\mathbf{n}$（形成一个环）。
3. **度数与边数定理**：
   - 无论是无向图还是有向图，**所有顶点的度数之和等于边数（弧数）的 2 倍**：$$\sum \text{Degree} = 2E$$。

## 📊 模块五：表达式求值、排序算法与查找长度 ASL 计算

### 1. 前缀、中缀与后缀表达式（逆波兰表达式）转换与计算
* **中缀表达式**：`a + b * c - (d + e)`
* **后缀表达式转换法则（笔试手工速算法）**：
  1. 按运算符优先级给所有运算加上括号：`((a + (b * c)) - (d + e))`
  2. 将每个括号内的运算符移到对应右括号的外面：`((a (b c)*)+ (d e)+)-`
  3. 去掉所有括号，得到后缀表达式：`a b c * + d e + -`
* **后缀表达式求值（栈应用）**：从左到右扫描，遇到数字入栈；遇到运算符弹出栈顶两个数字计算后压回栈顶。

---

### 2. 八大经典排序算法时空复杂度与稳定性全景表
| 排序算法 | 平均时间复杂度 | 最坏时间复杂度 | 空间复杂度 | 稳定性 | 考点特征 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **冒泡排序** | $O(N^2)$ | $O(N^2)$ | $O(1)$ | **稳定** | 交换相邻元素 |
| **直接插入排序**| $O(N^2)$ | $O(N^2)$ | $O(1)$ | **稳定** | 适合基本有序的小规模数据 |
| **折半插入排序**| $O(N^2)$ | $O(N^2)$ | $O(1)$ | **稳定** | 减少了比较次数，但移动次数不变 |
| **希尔排序** | $O(N^{1.3})$ | $O(N^2)$ | $O(1)$ | ❌ **不稳定** | 缩小增量排序 |
| **简单选择排序**| $O(N^2)$ | $O(N^2)$ | $O(1)$ | ❌ **不稳定** | 每次选最小放入头部 |
| **堆排序** | $O(N \log N)$ | $O(N \log N)$ | $O(1)$ | ❌ **不稳定** | 适合求 Top-K 大顶堆/小顶堆 |
| **快速排序** | $O(N \log N)$ | $\mathbf{O(N^2)}$ | $O(\log N)$ | ❌ **不稳定** | 原序有序时最坏退化为 $O(N^2)$ |
| **归并排序** | $O(N \log N)$ | $O(N \log N)$ | $O(N)$ | **稳定** | 分治思想，需额外辅助空间 |

> 💡 **稳定性速记口诀**：**“快选堆希不稳定”**（快速排序、选择排序、堆排序、希尔排序不稳定，其余经典排序均稳定）。

---

### 3. 哈希查找与平均查找长度 (ASL) 计算
* 给定长度为 11 的哈希表，散列函数 $H(key) = key \pmod 7$，线性探测法解决冲突：
  - **查找成功 ASL**：每个元素找到所需的比较次数之和 / 元素总个数；
  - **查找不成功 ASL**：每个哈希地址 $0 \sim 6$ 查找到第一个空单元格所需的比较次数之和 / 散列地址个数（此处为 7）。

## 🗄️ 模块六：SQL 语法、执行顺序与索引失效场景速查

### 1. SQL 语句的标准底层执行顺序
$$\mathbf{FROM} \rightarrow \mathbf{ON} \rightarrow \mathbf{JOIN} \rightarrow \mathbf{WHERE} \rightarrow \mathbf{GROUP\ BY} \rightarrow \mathbf{HAVING} \rightarrow \mathbf{SELECT} \rightarrow \mathbf{DISTINCT} \rightarrow \mathbf{ORDER\ BY} \rightarrow \mathbf{LIMIT}$$
* **【三大高频陷阱】**：
  1. `WHERE` 在 `GROUP BY` 前执行，**`WHERE` 后面绝不能跟 `COUNT/SUM/AVG` 聚合函数**（必须写在 `HAVING` 中）；
  2. `SELECT` 在 `WHERE` 之后执行，**`WHERE` 中不能使用 `SELECT` 中定义的别名**；
  3. `ORDER BY` 在 `SELECT` 之后执行，**`ORDER BY` 中可以使用列别名**。

---

### 2. 索引失效 7 大经典场景（口诀：模型数空运最左）
* **模**：前缀模糊查询（`LIKE '%abc'` 失效，`LIKE 'abc%'` 能走索引）；
* **型**：隐式类型转换（字符串字段不加引号 `WHERE phone = 180844` 失效）；
* **数**：在索引列上做运算或函数（`WHERE age + 1 = 18` 或 `WHERE SUBSTR(name,1,2)='张'` 失效）；
* **空**：`IS NOT NULL` 通常走全表；
* **运**：否定运算（`!=`、`<>`、`NOT IN` 范围过大走全表）；
* **最左**：违背最左前缀匹配（联合索引 `(a,b,c)` 查询 `WHERE b=1 AND c=2` 失效）；
* **OR 缺失**：`WHERE a=1 OR d=2`（若 `d` 无索引则全表扫描）。

---

### 3. SQL 中的 NULL 值陷阱
* `NULL = NULL` 的结果是 **`UNKNOWN`（假）**，必须使用 `IS NULL`；
* `COUNT(*)` 统计包含 NULL 行，但 **`COUNT(列名)` 会自动过滤掉该列为 NULL 的行**；
* `SUM()`, `AVG()`, `MIN()`, `MAX()` 均会自动忽略 NULL 值。

## 💾 模块七：MySQL 事务日志 (Redo/Undo/Binlog) 与锁机制

### 1. 三大日志核心职责对比
| 日志类型 | 写入方 | 日志格式 | 核心作用 | 事务提交时机 |
| :--- | :--- | :--- | :--- | :--- |
| **`Redo Log`（重做日志）** | InnoDB 存储引擎独有 | 物理日志（记录页修改） | **保证事务持久性（Crash-Safe 崩溃恢复）** | 事务执行中循环写，提交时两阶段提交 |
| **`Undo Log`（回滚日志）** | InnoDB 存储引擎独有 | 逻辑日志（记录相反逆操作） | **保证事务原子性与 MVCC 多版本快照读** | 事务执行前先写，事务回滚时使用 |
| **`Binlog`（归档日志）** | MySQL Server 层 | 逻辑日志（Statement/Row/Mixed） | **数据恢复、主从复制** | 事务提交时一次性写入 |

### 2. 事务四种隔离级别与并发问题
| 隔离级别 | 脏读（Dirty Read） | 不可重复读（Non-repeatable） | 幻读（Phantom Read） | 默认应用 |
| :--- | :--- | :--- | :--- | :--- |
| **读未提交（Read Uncommitted）** | ❌ 存在 | ❌ 存在 | ❌ 存在 | 极少使用 |
| **读已提交（Read Committed, RC）** | ✅ 解决 | ❌ 存在 | ❌ 存在 | Oracle / SQL Server 默认 |
| **可重复读（Repeatable Read, RR）** | ✅ 解决 | ✅ 解决 | ✅ 基本解决（MVCC+间隙锁） | **MySQL InnoDB 默认** |
| **串行化（Serializable）** | ✅ 解决 | ✅ 解决 | ✅ 解决 | 性能最差 |

## 🧠 模块八：JVM 内存模型、GC 算法与类加载机制考点

### 1. 各种变量在 JVM 中的存放位置
* **局部变量（基本类型及引用）**：存放在**虚拟机栈帧中的局部变量表**（线程私有）；
* **实例成员变量与对象**：存放在**堆（Heap）**中；
* **静态变量（`static`）**：存放在**堆 / 方法区**（JDK 8 存放在 Class 实例末尾）；
* **字符串常量字面量**：存放在**堆中的字符串常量池**。

---

### 2. 垃圾收集算法与分代比例
* **整堆比例**：`新生代 : 老年代 = 1 : 2`（新生代占 1/3，老年代占 2/3）；
* **新生代比例**：`Eden : S0 : S1 = 8 : 1 : 1`；
* **对象晋升老年代默认年龄**：**15 岁**（Mark Word 占 4 个 bit，最大 $2^4 - 1 = 15$）；
* **四种引用类型**：强引用（绝不回收） > 软引用（内存不足回收） > 弱引用（GC 必回收，`ThreadLocalMap.Entry` 采用） > 虚引用（仅用于堆外内存回收通知）。

## 🌐 模块九：计算机网络核心协议与 IP 子网/序号计算

### 1. IP 子网掩码与可用主机数计算（必考数学题）
* **【标准计算模型】**：
  - 给定 IP：`192.168.1.130/26`
  - 主机位数：$32 - 26 = 6$ 位；
  - 子网掩码：`255.255.255.192`；
  - 子网总 IP 数：$2^6 = 64$；
  - **可用主机数**：$2^6 - 2 = 62$（**必须扣除全 0 网络地址与全 1 广播地址**）；
  - 该 IP 所属子网：网络号为 `192.168.1.128`，广播号为 `192.168.1.191`。

---

### 2. TCP 序号与确认号计算
* **【计算规则】**：
  - 发送端发送的数据段：起始序号为 `seq = 101`，载荷数据长度为 `100 字节`；
  - 则该报文包含的字节序号区间为：`101 ~ 200`；
  - 接收端成功收到后，回复的确认号为：$\mathbf{ack = 201}$（表示前 200 字节已收到，期望下一次从 201 开始发）。

## 💻 模块十：操作系统进程管理、页面置换与磁盘调度计算

### 1. 银行家算法安全性检查（判断死锁避免）
* **矩阵关系**：$$\mathbf{Need = Max - Allocation}$$
* **安全性算法判断**：查找是否存在一个进程 $P_i$，其 $Need_i \le Available$。若找到，模拟该进程执行完毕并释放已分配资源：$$Available_{new} = Available + Allocation_i$$，重复检查能否找到安全序列。

---

### 2. 常见磁盘调度算法寻道顺序
* 给定磁头初始位置在 `100` 号磁道，请求队列为 `[55, 58, 39, 18, 90, 160, 150, 38, 184]`：
  - **FCFS（先来先服务）**：按数组原始顺序逐一访问；
  - **SSTF（最短寻道时间优先）**：每次选择距离当前磁头最近的磁道；
  - **SCAN（电梯算法）**：磁头按一个固定方向（如向大号磁道）移动并顺路访问，到达最边缘后再反向移动访问。

## ⚡ 终极附录：秋招笔试选择题 50 条一秒破局秒杀口诀

1. **`i = i++`** 结果永远是原值，`i = ++i` 才是增加后的值。
2. **`Integer`** 在 `[-128, 127]` 范围用 `==` 是 `true`，超出是 `false`；包装类与基本类型 `==` 永远拆箱比数值。
3. **`String`** 字面量相加在常量池，带变量相加在堆上 `new StringBuilder`。
4. **`try-finally`** 中，`finally` 里的 `return` 吞掉一切返回值和未捕获异常。
5. **父子类加载顺序**：父类静态 $\rightarrow$ 子类静态 $\rightarrow$ 父类构造 $\rightarrow$ 子类构造。
6. **多态调用**：方法看右边（子类重写），成员变量和静态方法看左边（父类声明）。
7. **重写规则**：两同两小一大，子类访问权限绝不能小于父类，`private` 无法重写。
8. **二叉树叶子公式**：$n_0 = n_2 + 1$，叶子节点永远等于度为 2 的节点数加 1。
9. **完全二叉树编号**：节点 $i$ 的左孩子是 $2i$，右孩子是 $2i+1$，父节点是 $\lfloor i/2 \rfloor$。
10. **无向完全图边数**：$\frac{n(n-1)}{2}$，有向完全图弧数：$n(n-1)$。
11. **图的度数与边数**：所有顶点度数之和等于边数的 2 倍（$\sum D = 2E$）。
12. **排序稳定性口诀**：**快选堆希不稳定**（快排、选择、堆排、希尔不稳定，其余稳定）。
13. **快排最坏时间复杂度**：当输入数组完全有序时，退化为 $O(N^2)$。
14. **SQL 执行顺序**：`FROM` 最先跑，`WHERE` 在分组前，`HAVING` 在分组后，`ORDER BY` 倒数第二，`LIMIT` 最后。
15. **`WHERE` 陷阱**：`WHERE` 后面绝对不能加 `COUNT/SUM` 聚合函数。
16. **索引失效口诀**：**模型数空运最左**（模糊前置、类型转换、列上函数、判空、否定运算、违背最左匹配）。
17. **SQL 的 `NULL`**：`NULL = NULL` 是假，`COUNT(*)` 算 NULL，`COUNT(列)` 忽略 NULL。
18. **JVM 变量位置**：局部变量在栈，对象和成员变量在堆，静态变量在堆/方法区。
19. **分代年龄最大值**：15 岁（Mark Word 占 4 个 bit）。
20. **堆新生代比例**：`Eden:S0:S1 = 8:1:1`，新生代占整堆 1/3。
21. **子网计算**：可用主机数一定要减 2（扣除网络地址和广播地址）。
22. **HTTP 304** 是协商缓存未修改，**301** 是永久重定向，**302** 是临时重定向。
23. **HTTP 502** 是网关连不上后端，**504** 是网关等后端超时。
24. **进程状态流转**：阻塞态绝对不能直接变运行态，必须先回就绪态。
25. **页面置换 Belady 异常**：只有 FIFO 算法会出现物理页增多缺页反而增加的现象。
26. **`HashMap` 树化条件**：链表长度 $\ge 8$ 且数组总容量 $\ge 64$。
27. **`HashMap` 初始容量**：总是扩充为 2 的幂次方（为了用 `hash & (n-1)` 代替取模运算 `%`）。
28. **线程启动**：调用 `start()` 启动新线程，直接调用 `run()` 只是主线程普通方法调用。
29. **`volatile` 两大作用**：保证可见性、禁止指令重排，但**不保证原子性**。
30. **死锁破坏**：破坏请求与保持（一次性申请）、破坏循环等待（按固定递增顺序拿锁）。
31. **`short s1 = 1; s1 += 1;`** 编译正常，`s1 = s1 + 1` 编译报错（类型提升为 int）。
32. **`byte b = (byte) 130;`** 输出是 -126（8 位补码截断）。
33. **泛型 PECS 原则**：`<? extends T>` 只读不写，`<? super T>` 只写不读。
34. **Java 异常**：`Error` 和 `RuntimeException` 是非受检异常，其余为受检异常（编译期强检）。
35. **线程方法**：`sleep()` 不释放锁，`wait()` 释放锁，`yield()` 让出 CPU 回就绪态。
36. **后缀表达式求值**：从左到右扫描，遇到数字入栈，遇到符号弹两个算完压回。
37. **MySQL Redo Log**：物理日志，保证持久性 Crash-Safe；**Undo Log**：逻辑日志，保证原子性与 MVCC。
38. **MySQL Binlog**：Server 层逻辑日志，用于数据恢复与主从复制。
39. **`DELETE` vs `TRUNCATE`**：`DELETE` 是 DML 逐行删除记日志可回滚；`TRUNCATE` 是 DDL 重置自增 ID 速度极快不可回滚。
40. **TCP 首部**：固定 20 字节，最大 60 字节。
41. **TCP 确认号**：若收到 `seq = 101` 且长度为 `100` 的报文，确认号 `ack = 201`。
42. **哈希冲突解决**：开放寻址法、链地址法（拉链法）、再哈希法。
43. **拓扑排序**：适用于有向无环图 (DAG)，入度为 0 的顶点入队。
44. **LRU 置换**：淘汰最长时间未访问的页；**LFU**：淘汰访问频次最低的页。
45. **二叉树深度 $k$ 最多节点数**：$2^k - 1$；第 $i$ 层最多 $2^{i-1}$ 个节点。
46. **`Float` 和 `Double`** 包装类**没有任何缓存池**，每次赋值都是新对象。
47. **`0.1 + 0.2 == 0.3`** 在 Java 中为 `false`（浮点精度丢失），必须用 `BigDecimal("0.1")`。
48. **`ConcurrentModificationException`**：在 `for-each` 遍历集合时调用 `list.remove()` 必抛异常，应使用 `iterator.remove()`。
49. **类加载器层级**：启动类加载器 (Bootstrap) $\rightarrow$ 扩展类加载器 (Extension) $\rightarrow$ 应用程序类加载器 (Application)。
50. **双亲委派机制**：优先向上委派给父加载器加载，父加载器无法加载才由子加载器尝试加载。
