# B4 — 商城 AI 助手 RAG 知识检索与规则问答系统实施计划

> **阶段**: Stage 3 (B4 · `feat/ai-stage3-rag`)
> **目标**: 为荒天享物电商 AI 助手实现企业级 RAG（检索增强生成）知识库与规则问答体系，支持商品长文本/规格参数、商城通用售后规则与商家服务的精准召回，并在系统提示词中安全注入。
> **代码规范与注释要求**: 遵循阿里巴巴 Java 开发规范与 SRP（单一职责，每类 < 350 行），编写详尽的教学级专业注释（向量空间几何含义、余弦相似度公式、RAG 管道生命周期），严格遵循 `no-negative-echo` 规范。

## 架构全景设计 (Architecture Design)

```
                       ┌────────────────────────────────────────────────────────┐
                       │                     用户输入 Query                     │
                       └───────────────────────────┬────────────────────────────┘
                                                   │
                                                   ▼
┌────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│                                       1. 向量嵌入层 (Embedding Layer)                                  │
│                                                                                                        │
│   Query ──▶ [CachedEmbeddingService] ──(Redis 缓存命中?)──YES──▶ 取得 float[1024]                      │
│                           │ (NO)                                                                       │
│                           ▼                                                                            │
│                [DashScopeEmbeddingService]  /  [MockEmbeddingService] (单测/本地离线兜底)               │
└──────────────────────────────────────────┬─────────────────────────────────────────────────────────────┘
                                           │
                                           ▼
┌────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│                                       2. 向量检索层 (VectorStore Layer)                                │
│                                                                                                        │
│   float[1024] ──▶ [MysqlVectorStore] ──▶ [VectorMathUtils.cosineSimilarity]                           │
│                           │                                                                            │
│                           ▼                                                                            │
│             Top-K 相似度过滤 (minScore ≥ 0.65, 租户元数据多维过滤)                                      │
└──────────────────────────────────────────┬─────────────────────────────────────────────────────────────┘
                                           │
                                           ▼
┌────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│                                 3. 安全防御与上下文注入 (Sanitize & Inject)                            │
│                                                                                                        │
│   Knowledge Chunk ──▶ [PromptSanitizer] (3层防御) ──▶ <UNTRUSTED_KNOWLEDGE> 标签隔离                   │
│                                │                                                                       │
│                                ▼                                                                       │
│             [KnowledgeRecallInjector] ──▶ 注入到 LLM System Prompt (<knowledge_hits>)                  │
│                                或供 [SearchKnowledgeTool] 显式工具调用                                 │
└────────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

## 教学级代码注释规范要求

所有代码必须包含详尽的专业 JavaDoc 与行内注释，涵盖：
1. **向量数学原理**：解释什么是高维稠密向量（Dense Vector）、为什么使用余弦相似度度量语义距离；
2. **企业级架构考量**：解释为什么分层（Service -> VectorStore -> MathUtils）、为什么引入本地 Mock 与 Redis 缓存、如何防止 API 限流；
3. **安全边界设计**：说明 RAG 场景下的“间接 Prompt 注入”（Indirect Prompt Injection）防御机制与隔离标签设计；
4. **零退化设计**：说明为什么所有开关默认关闭，以及如何做到关掉开关后与原有代码字节级一致。
